# METRA — GOVERNANCE MIGRATION CANON

## Constitutional Workspace Migration Method

**STATUS**

CANONICAL DOMAIN PRINCIPLE


## PURPOSE

This canon defines the approved method for migrating an operational
capability from embedded ownership into constitutional workspace
ownership.


## CORE PRINCIPLE

A capability should not own the responsibility that determines when
that capability is engaged.

Responsibility and execution must be separated.


## CONSTITUTIONAL HAND-OFF MODEL

Every migration is analysed as a sequence of hand-offs:

Responsibility

↓

Constitutional Entry

↓

Constitutional Destination

↓

Lifecycle Owner

↓

Capability


## MIGRATION METHOD


### 1. State the Constitutional Contract

Define:

- responsibility being exercised
- expected destination
- expected owner


### 2. Identify Current and Future Owners

Identify:

Current owner

↓

Future owner


The migration begins with ownership, not implementation.


### 3. Inspect the Hand-Off

Inspect only the seam between owners.

Ask:

"Has the constitutional contract been honoured?"


### 4. Create the Workspace Boundary

The workspace provides:

- constitutional destination
- responsibility context
- lifecycle separation


The workspace does not replace the capability.


### 5. Transfer Lifecycle Ownership

The provider owns:

- workspace state
- lifecycle entry
- event opening
- coordination


The capability retains:

- operational behaviour
- domain rules
- existing functionality


### 6. Remove Embedded Ownership

The previous surface releases:

- lifecycle state
- routing decisions
- domain coordination


It may continue to:

- reveal options
- pass context
- preserve continuity


### 7. Verify Completion

A migration requires:

1. Behavioural hand-off

The user reaches the correct destination.


2. Ownership hand-off

The new owner controls lifecycle.


3. Repository hand-off

The ownership boundary exists in version history.


## STAGE 500 PROOF

The method was proven through:

- Risk exemplar migration
- CC migration
- Issue migration
- QC migration


## FORBIDDEN PATTERNS

Do not:

- create a new capability when one exists
- move UI without moving ownership
- leave lifecycle state in the old surface
- invent a new migration method when an exemplar exists


## CANONICAL RULE

Reuse before invent.

Inspect before mutate.

Transfer ownership before removing structure.

Baseline only after ownership exists.
